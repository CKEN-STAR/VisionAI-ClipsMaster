# 方案B·微调（索引目标 + 最小数量保障）

## 背景/上下文
- JSON 优先路径在长上下文下仍频繁失败；索引模式已能产出，但常仅 2 条/批。
- 目标：不改动外部行为与兜底链（JSON → 索引 → SRT → 规则）的前提下，提高“AI直出条数”，减少对规则引擎依赖，恢复/提升总体片长。

## 本次改动（最小侵入）
1) 索引模式提示词加强
   - 新增目标数量指引：优先选择并重排 15–30 条；若不足，尽量接近 15 条。
   - 中英文双路径同步；仍保持“仅返回索引数组、不得有任何额外文本”的强约束。

2) 最小数量保障补齐逻辑（仅当索引模式非空但不足阈值时触发）
   - 阈值：min(16, 批大小)。
   - 先按与剧情摘要的相似度进行补齐（阈值参考 0.55，综合长度/标点加权），再不足用规则引擎补齐。
   - 统一去重与重新编号；新增日志：索引原始 M、相似度补齐 X、规则补齐 Y、最终 Z。

3) 其他
   - 不改变扣时间轴的末尾流程，仍统一重排时轴。
   - 不改变外部 API/配置；失败时仍按原回退链路运行。

## 受影响代码
- src/core/real_ai_engine.py
  - _build_batch_merge_prompt_indices：提示词新增“目标数量”条目
  - 新增 _ensure_minimum_index_result：最小数量保障/补齐
  - 批处理主循环：索引模式解析成功但数量不足时调用补齐逻辑

## 验证要点（请用同一素材复跑 UI 全流程）
- 日志应出现：
  - “第N批（索引-补齐）目标≥X：索引M + 相似度补齐X + 规则补齐Y → 最终Z”
  - “第N批：生成 Z 条混剪字幕”中 Z 明显提升（期望 ≥16/批，允许小幅波动）
- 汇总：总条数、总时长较上一轮显著增加；回退至规则引擎的比例下降。

## 回滚/风险
- 变更集中于 RealAIEngine 内部；若需回滚，移除补齐调用与新增函数即可。
- 未引入依赖/配置变更，风险极低。
