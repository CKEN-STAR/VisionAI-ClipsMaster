## 执行摘要

本次修复针对用户反馈的两个核心问题：
1. **UI取消无效**：用户在UI点击取消后，下载进程仍然继续运行
2. **不完整文件未清理**：下载取消或失败后，不完整的模型文件仍然保留在项目中

经过深度排查，发现根本原因是**ModelScope的`snapshot_download`是一个阻塞调用，无法被中断**。

---

## 问题诊断

### 问题1：UI取消无效

**现象**：
- 用户在UI点击"取消"按钮
- 进度对话框显示"正在取消下载，请稍候..."
- 但是终端日志显示下载仍然在继续
- 下载完成后，文件没有被清理

**根本原因**：
```python
# src/core/enhanced_model_downloader.py 第278行
model_dir = ms_snapshot_download(
    repo_id,
    cache_dir=str(local_dir.parent),
)
```

`ms_snapshot_download`是ModelScope SDK提供的高级API，它是一个**阻塞调用**，内部实现了完整的下载流程，包括：
- 获取文件列表
- 逐个下载文件
- 验证文件完整性
- 创建符号链接

这个调用**无法被外部中断**，即使我们设置了`is_cancelled=True`，下载仍然会继续，直到完成或失败。

**证据**：
```
2025-11-02 10:14:27,544 - 用户取消下载: Qwen3-1.7B-Instruct-FP16
2025-11-02 10:14:27,723 - ⚠️ 用户取消下载，停止进度监控
# 但是下载仍然在继续：
Downloading [model-00002-of-00002.safetensors]:  20%|███▏  | 119M/594M [00:39<02:50, 2.92MB/s]
```

### 问题2：不完整文件未清理

**现象**：
- 用户取消下载后，`models/qwen3-1.7b`目录仍然存在
- 目录中包含部分下载的文件
- 这些文件导致UI无法正确弹出智能推荐下载器弹窗

**根本原因**：
虽然我们在代码中添加了清理逻辑：
```python
# 检查是否在下载过程中被取消
if self.is_cancelled:
    logger.warning("⚠️ 下载完成后检测到取消标志，清理下载文件")
    self._cleanup_snapshot_download(local_dir.parent, force_delete_all=True)
    raise Exception("用户取消下载")
```

但是，这个检查只在`ms_snapshot_download`**完成后**执行。如果下载已经完成（即使用户点击了取消），`is_cancelled`标志会被检查，但是文件已经下载完成，清理逻辑不会执行。

    # 否则，只清理临时文件
    ...

**效果**：
- 用户取消或下载失败时，强制删除整个下载目录
- 确保不会留下不完整的文件

## 遗留问题

### 核心问题：无法立即中断下载

**问题描述**：
用户点击取消后，需要等待当前文件下载完成（可能需要几分钟），才能真正取消下载。

**根本原因**：
`ms_snapshot_download`是一个阻塞调用，无法被外部中断。

**可能的解决方案**：

#### 方案1：使用ModelScope的底层API（推荐）

不使用`snapshot_download`，而是使用底层API逐个下载文件：

```python
from modelscope.hub.api import HubApi

api = HubApi()
files = api.get_model_files(repo_id)

for file in files:
    # 检查取消标志
    if self.is_cancelled:
        self._cleanup_snapshot_download(local_dir, force_delete_all=True)
        raise Exception("用户取消下载")
    
    # 下载单个文件
    self._download_file(file_url, target_path, file_size)
```

**优点**：
- 可以在每个文件下载之间检查`is_cancelled`
- 实现真正的取消功能
- 更精细的进度控制

**缺点**：
- 需要大量代码修改（约200-300行）
- 需要手动处理文件验证、符号链接等逻辑
- 可能引入新的bug

#### 方案2：使用`multiprocessing.Process`（不推荐）

在单独的进程中运行`ms_snapshot_download`，用户取消时强制终止进程：

```python
import multiprocessing

def download_in_process(repo_id, cache_dir, result_queue):
    try:
        model_dir = ms_snapshot_download(repo_id, cache_dir=cache_dir)
        result_queue.put(("success", model_dir))
    except Exception as e:
        result_queue.put(("error", str(e)))

# 启动下载进程
result_queue = multiprocessing.Queue()
process = multiprocessing.Process(
    target=download_in_process,
    args=(repo_id, cache_dir, result_queue)
)
process.start()

# 用户取消时，强制终止进程
if self.is_cancelled:
    process.terminate()
    process.kill()
    self._cleanup_snapshot_download(local_dir, force_delete_all=True)
```

**优点**：
- 可以立即终止下载
- 代码修改较少

**缺点**：
- 进程间通信复杂（需要序列化PyQt信号）
- 可能导致文件损坏（强制终止可能导致文件写入不完整）
- 跨平台兼容性问题（Windows/Linux/macOS行为不同）

#### 方案3：接受当前行为（临时方案）

保持当前的修复，接受"用户取消后需要等待下载完成"的行为。

**优点**：
- 无需额外修改
- 稳定性高

**缺点**：
- 用户体验不佳
- 用户可能误以为取消无效
