# 内存阈值动态化（A方案）最小改动记录

## 背景
- 日志显示：在 16GB 设备上，进程 RSS ≈ 9.3GB，但阈值固定 3.5–3.8GB，导致频繁触发“内存压力/严重不足”告警；虽然不影响结果，但噪声多且触发了少量策略降级（如剧情分析阶段回退规则法）。
- 目标：在不改变核心功能的前提下，将内存阈值改为“按系统内存动态计算（≈70%）”，并保持环境/配置可覆盖，降低误报与不必要降级。

## 改动内容（最小且可回退）
1) src/performance/memory_optimizer.py
- 将 `MemoryOptimizer.__init__` 默认参数由固定 `3800` 改为 `None`。
- 当未显式传入时：
  - 优先调用 `src.config.env_adapter.get_optimal_memory_limit()` 获取建议上限；
  - 若失败则回退为 `psutil.virtual_memory().total * 0.70`；
  - 将 `model_cache`/`data_cache` 的内存配额基于最终 `self.memory_limit_mb` 计算（0.7/0.2）。

2) src/core/ai_plot_analyzer.py
- 将原 `self.memory_limit_mb = int(os.getenv("VACL_MEMORY_LIMIT_MB", "3500"))` 改为：
  - 若设置了 `VACL_MEMORY_LIMIT_MB` 环境变量则优先使用；
  - 否则优先 `get_optimal_memory_limit()`；
  - 再次失败时回退 `psutil.total * 0.70`；如 `psutil` 不可用，最终保守回退 `3500`。

## 兼容性与风险
- 改动均为“默认值策略”调整，对外部 API/调用点无破坏性变更；
- 环境变量与配置仍可覆盖，易于回退；
- 未修改功能逻辑、仅影响触发阈值与告警频率。

## 预期效果
- 在 16GB 机器上，动态阈值 ≈ 11.2GB；此前 ~9.3GB 不再触发“内存压力”告警；
- ai_plot_analyzer 不再在非必要情况下暂停 LLM 调用，减少无谓的回退与日志噪声；
- 统一与平台适配策略（env_adapter）保持一致。

## 建议的后续验证
- 运行一次 UI 的“直接混剪”或“工作流程模式”，观察 logs/visionai.log：
  - 不应再出现 `(XXXXMB/3500MB)` 类固定阈值日志；
  - MemoryOptimizer 的“进程内存使用过高”告警仅在接近动态阈值 *0.9 时出现；
- 单元/烟测：导入 `AIPlotAnalyzer` 与 `get_memory_optimizer()` 打印阈值（本次已完成快速烟测）。

## 回退方式
- 将上述两处改动回退到固定 MB 即可（3800/3500）。
