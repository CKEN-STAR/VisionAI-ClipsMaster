## 🔧 详细流程说明

### 阶段1：初始化

**目的**：下载并准备基础模型

**执行命令**：
```bash
python scripts/setup_models_integrated.py
```

**内部流程**：
1. 调用 `EnhancedModelDownloader` 智能推荐下载器
2. 根据网络状况选择最佳下载源
3. 下载HuggingFace格式模型到 `models/qwen/base/`
4. 调用 `ModelConverter` 转换为GGUF格式
5. 保存GGUF模型到 `models/qwen/quantized/`

**输出**：
- ✅ HuggingFace格式基础模型（用于训练）
- ✅ GGUF格式基础模型（用于推理）

---

### 阶段2：训练

**目的**：使用用户数据微调模型

**执行代码**：
```python
from src.training.zh_trainer import ZhTrainer

trainer = ZhTrainer()
result = trainer.train(
    training_data=[
        {"input": "原文1", "output": "翻译1"},
        {"input": "原文2", "output": "翻译2"},
        # ...
    ],
    num_epochs=3,
    batch_size=2,
    learning_rate=2e-5
)
```

**内部流程**：
1. 加载HuggingFace格式基础模型
2. 应用LoRA适配器（rank=16, alpha=32）
3. 使用用户数据进行微调
4. 保存训练结果到 `./results_zh/`

**输出**：
- ✅ 微调后的HuggingFace格式模型

---

### 阶段3：版本注册

**目的**：注册训练后的模型版本，管理多个训练版本

**自动触发**：训练完成后自动执行

**内部流程**：
1. 调用 `_register_trained_version()`
2. 生成版本ID（格式：`v{YYYYMMDD}_{HHMMSS}`）
3. 创建版本目录结构
4. 保存HuggingFace格式模型路径
5. 更新 `versions.json`
6. 自动清理旧版本（保留最近5个）
7. 💡 提示用户在UI中手动转换为GGUF

**输出**：
- ✅ 版本化的HuggingFace模型存储
- ✅ 版本元数据（versions.json）
- ✅ 提示信息：训练完成！请在UI中手动转换为GGUF格式以用于推理

---

### 阶段4：手动转换 🆕

**目的**：将训练后的模型转换为GGUF格式用于推理

**手动触发**：用户在UI的模型管理界面点击"🔄 转换为GGUF"按钮

**为什么要手动转换？**
- ✅ 避免每次训练都自动转换，节省时间和存储空间
- ✅ 用户可以选择性地转换需要的版本
- ✅ 可以在训练多次后，只转换最满意的版本

**内部流程**：
1. 用户在模型管理界面选择一个训练版本
2. 点击"🔄 转换为GGUF"按钮
3. 系统读取HuggingFace格式模型
4. 使用 `ModelConverter` 转换为GGUF格式
5. 应用Q4_K_M量化（中文）或Q5_K量化（英文）
6. 保存到 `models/qwen/quantized/trained/`
7. 更新版本信息中的GGUF路径

**UI操作步骤**：
```
1. 打开设置标签页 → 模型管理
2. 在"训练模型版本列表"中选择要转换的版本
3. 点击"🔄 转换为GGUF"按钮
4. 等待转换完成（显示进度对话框）
5. 转换完成后自动进行性能评估
```

**输出**：
- ✅ GGUF格式训练模型（用于推理）
- ✅ 更新的版本信息

---

### 阶段5：性能评估 🆕

**目的**：评估新转换的GGUF模型性能，为智能切换提供依据

**自动触发**：GGUF转换完成后自动执行

**内部流程**：
1. 调用 `PerformanceEvaluator.evaluate_model()`
2. 使用默认验证数据集（5个测试样本）
3. 计算性能分数（0-1之间）
4. 更新版本信息中的 `performance_score`

**评估指标**：
- 准确率
- 推理速度
- 综合性能分数

**输出**：
- ✅ 性能分数（保存在versions.json中）
- ✅ 在UI中显示性能分数

---

### 阶段6：智能切换 🆕

**目的**：基于性能智能选择最佳模型（方案三）

**自动触发**：性能评估完成后自动执行

**决策逻辑**：
```python
if 没有激活模型:
    自动激活新模型
elif 新模型性能 > 当前模型性能:
    询问用户是否切换
    显示性能提升百分比
else:
    提示保留当前模型
    显示性能下降百分比
```

**UI交互**：
- 如果新模型性能更好：弹出对话框询问是否切换，显示性能提升
- 如果新模型性能较差：提示保留当前模型，显示性能对比

**输出**：
- ✅ 激活最佳性能的模型（如果用户同意）
- ✅ 记录切换决策和性能变化

---

### 阶段7：推理

**目的**：使用最佳模型进行推理

**执行代码**：
```python
from src.inference.model_loader import InferenceModelLoader

loader = InferenceModelLoader("qwen2.5-7b-zh")
model_path, model_type = loader.get_best_model_path()

# model_type 可能的值:
# - "trained": 使用训练后的模型
# - "base": 使用基础模型
```

**内部流程**：
1. 读取 `versions.json` 获取激活版本
2. 优先加载激活的训练模型（GGUF格式）
3. 如果没有训练模型，使用基础模型
4. 返回模型路径和类型

**输出**：
- ✅ 最佳模型路径（用于推理）

## 🔍 故障排查

### 问题1：性能评估失败

**症状**：训练完成后显示"性能评估失败，使用默认策略"

**原因**：
- 验证数据集不可用
- 模型加载失败
- 评估过程出错

**解决方案**：
- 检查日志中的详细错误信息
- 确保模型文件完整
- 如果持续失败，系统会降级到方案一（自动激活新模型）

### 问题2：模型切换未生效

**症状**：训练后仍使用旧模型

**原因**：
- 新模型性能低于当前模型
- 版本管理系统未正确更新

**解决方案**：
- 查看日志中的性能比较信息
- 手动在UI中切换激活模型
- 检查 `versions.json` 文件

### 问题3：GGUF转换失败

**症状**：训练完成但没有生成GGUF模型

**原因**：
- llama-cpp-python未正确安装
- 模型格式不兼容
- 磁盘空间不足

**解决方案**：
- 重新安装llama-cpp-python
- 检查磁盘空间
- 查看转换日志
