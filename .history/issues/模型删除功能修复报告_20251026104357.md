## ✅ 修复方案

### 修复1：训练模型删除时同时删除合并模型

**修改文件**：`src/training/model_version_manager.py`  
**修改位置**：第227-263行

**修改内容**：
```python
# 引用模式：根据参数决定是否删除原始文件
if version_info.get("copy_mode") == "reference":
    if delete_actual_files:
        # 删除原始模型文件
        hf_path = version_info.get("hf_path")
        if hf_path and Path(hf_path).exists():
            try:
                shutil.rmtree(hf_path)
                logger.info(f"   已删除原始模型文件: {hf_path}")
            except Exception as e:
                logger.error(f"   删除原始模型文件失败: {e}")

        # 删除GGUF文件（如果有）
        gguf_path = version_info.get("gguf_path")
        if gguf_path and Path(gguf_path).exists():
            try:
                Path(gguf_path).unlink()
                logger.info(f"   已删除GGUF文件: {gguf_path}")
            except Exception as e:
                logger.error(f"   删除GGUF文件失败: {e}")
        
        # 🔧 修复：删除合并模型（如果有）
        merged_dir = self.base_dir / "merged"
        if merged_dir.exists():
            try:
                # 检查合并模型是否存在
                merged_files = list(merged_dir.glob("*.safetensors")) + list(merged_dir.glob("*.bin"))
                if merged_files:
                    logger.info(f"   检测到合并模型文件: {len(merged_files)}个")
                    # 删除整个merged目录
                    shutil.rmtree(merged_dir)
                    logger.info(f"   已删除合并模型目录: {merged_dir}")
            except Exception as e:
                logger.error(f"   删除合并模型失败: {e}")
    else:
        logger.info(f"   引用模式版本，只移除记录，不删除原始文件")
    return
```

**修复说明**：
- 在删除训练模型时，检查 `models/qwen/merged` 目录
- 如果存在合并模型文件（`.safetensors` 或 `.bin`），删除整个 `merged` 目录
- 添加异常处理，确保删除失败不会影响其他操作

### 修复2：基础模型删除时同时删除合并模型

**修改文件**：`simple_ui_fixed.py`  
**修改位置**：第8058-8108行

**修改内容**：
```python
if reply == QMessageBox.StandardButton.Yes:
    try:
        import shutil
        if model_path.exists():
            # 删除整个模型目录
            shutil.rmtree(model_path)

            merged_dirs_to_check = [
```

- 在成功消息中告知用户删除了多少个合并模型

## 📝 用户问题解答

### 问题1：删除训练模型后，GGUF模型列表立即消失

**回答**：这是**正确的行为**，不是Bug。

**原因**：
- 删除训练模型时，系统会**同时删除对应的GGUF模型**
- 这是因为GGUF模型是从训练模型转换而来的
- 删除训练模型后，GGUF模型也应该被删除
- 所以GGUF列表消失是正确的

**日志证据**：
```
2025-10-26 10:29:04,337 - src.training.model_version_manager - INFO -    已删除GGUF文件: models\qwen\quantized\trained_20251026_101751_Q4_K_M_f16.gguf
```

### 问题2：删除基础模型后，项目体积只下降了部分

**回答**：这是**Bug**，已修复。

**原因**：
- 删除基础模型时，**没有删除合并模型**
- 合并模型是基础模型 + LoRA适配器的合并结果，体积很大（2944MB）
- 删除基础模型后，合并模型成为"孤儿文件"，仍然占用空间

**修复**：
- 现在删除基础模型时，会**自动检查并删除所有合并模型**
- 删除后会显示"同时删除了 X 个合并模型目录"
- 项目体积会完全下降

## 🎯 使用建议

### 正确的删除顺序

**如果要完全清理模型**：
1. 删除训练模型（会自动删除GGUF模型和合并模型）
2. 删除基础模型（会自动删除所有合并模型）

**如果只想删除GGUF模型**：
- 在"GGUF推理模型"列表中单独删除GGUF文件
- 不会影响训练模型和基础模型

### 模型关联关系

```
基础模型 (models/qwen2.5-1.5b/fp16)
    ↓
训练模型 (models/qwen/finetuned) ← LoRA适配器
    ↓
合并模型 (models/qwen/merged) ← 基础模型 + LoRA适配器
    ↓
GGUF模型 (models/qwen/quantized/*.gguf) ← 从合并模型转换
```

**删除影响**：
- 删除基础模型 → 无法训练新模型
- 删除训练模型 → 合并模型和GGUF模型一起删除
- 删除合并模型 → GGUF模型可能无法使用
- 删除GGUF模型 → 不影响其他模型
