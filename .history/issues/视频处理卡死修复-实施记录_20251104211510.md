标题：视频处理卡死/无响应问题修复 - 实施记录

时间：2025-11-04
负责人：Augment Agent

一、问题概述
- 现象：真实短剧素材处理时在“AI剧情分析/剧本重构”阶段卡死/无响应；内存长期高位（~6.7GB/配置3.8GB），FFmpeg偶发阻塞。
- 关键日志：
  - 多次出现“开始调用GGUF模型生成响应...”后长时间无进一步输出
  - 偶发一次性输出近5k字符且JSON结构混乱，随后再次触发生成
  - 内存优化器高频清理但无法降低占用

二、根因定位
- llama-cpp-python 同步调用缺少超时与进度反馈，复杂长提示词易导致长时间阻塞
- FFmpeg/ffprobe 子进程未设超时，异常时主进程阻塞
- 提示词过长（多集拼接）→ 上下文窗口压力大、推理耗时极长、内存高位
- 验证/后续步骤会多次触发生成（非死循环，步骤链路导致的多次调用）

三、修复措施（已实施）
1) RealAIEngine 推理安全化
- 在 _generate_response 增加：
  - 流式生成 create_completion(stream=True) 支持
  - generation_timeout_sec（默认600s）超时控制，超时返回部分结果
  - 每5秒进度日志："GGUF生成中... 已输出N字符, 用时Xs"
  - 提示词安全截断 max_prompt_chars（默认20000）
  - 兼容无流式接口的旧模型路径
- 位置：src/core/real_ai_engine.py 行1906附近

2) ClipGenerator 子进程稳健性
- 为 ffprobe/ffmpeg 添加 timeout：
  - ffprobe 获取媒体信息：15s
  - ffprobe 获取时长：10s
  - ffmpeg 切割/拼接：600s（可由 performance.ffmpeg_timeout_sec 配置）
  - 超时时 GPU→CPU 回退一次，仍失败则失败返回，避免无限等待
- 位置：src/core/clip_generator.py（切割/拼接/探测相关方法）

四、兼容性与影响
- 完全向后兼容：未改变外部接口与核心流程；新增配置项具备默认值
- 失败快速返回：避免“卡死”观感，日志可见进度/超时与回退行为

五、验证建议
- CLI：
  - python app.py --video <真实视频> --subtitle <对应SRT> --preset viral_mix --log-level INFO
  - 观察日志：
    - RealAI: "开始调用GGUF..." 后应出现周期性 "GGUF生成中... 已输出..."
    - 超时将记录 "GGUF生成超时(...)，返回部分结果"
    - FFmpeg阶段若阻塞，将在超时后回退到CPU并记录错误
- 配置可调：configs/model_config.* → generation_timeout_sec, max_prompt_chars；configs/clip_settings.json → performance.ffmpeg_timeout_sec

六、后续优化建议（未实施，待评审）
- 七步算法的分批/分集聚合提示词，降低单次prompt长度
- 针对JSON结构化输出加入“格式修复器+有限重试（上限1-2次）”的断路器
- 与内存优化器联动的“生成自降级”（缩短max_tokens、提高stop概率）
