## 功能概述

### 什么是模型管理功能？

模型管理功能是VisionAI-ClipsMaster的核心功能之一，用于管理AI模型的训练版本、激活状态、格式转换等操作。

### 主要功能

1. **版本管理**：记录和管理所有训练模型版本
2. **自动检测**：自动检测现有的训练模型并注册
3. **激活切换**：在不同版本之间切换激活状态
4. **格式转换**：将HuggingFace格式转换为GGUF格式
5. **模型删除**：删除不需要的模型版本
6. **详情查看**：查看模型的训练参数和配置
7. **基础模型管理**：管理下载的基础模型

## 架构设计

### 目录结构

```
models/
├── qwen/                          # 中文模型家族
│   ├── finetuned/                 # 训练后的模型（原始位置）
│   │   ├── adapter_model.safetensors
│   │   ├── adapter_config.json
│   │   ├── tokenizer.json
│   │   └── training_config.json
│   ├── trained/                   # 版本管理目录
│   │   └── versions.json          # 版本记录文件
│   └── quantized/                 # GGUF格式模型
│       └── trained/               # 训练后的GGUF模型
├── qwen2.5-1.5b/                  # 基础模型
│   └── fp16/                      # FP16格式
└── mistral/                       # 英文模型家族
    ├── finetuned/
    ├── trained/
    └── quantized/
```

### 设计原则

1. **引用模式**：不复制模型文件，只记录路径引用
2. **原地管理**：模型始终保持在原始位置（`finetuned/`）
3. **元数据分离**：版本信息存储在独立的 `versions.json` 文件
4. **自动化**：自动检测和注册现有模型
5. **向后兼容**：不影响现有功能和路径依赖

## 核心组件

### 1. ModelVersionManager

**文件位置**：`src/training/model_version_manager.py`

**职责**：
- 管理模型版本的注册、激活、删除
- 维护 `versions.json` 文件
- 提供版本查询和统计功能

**核心方法**：

#### `register_new_version(model_path, gguf_path, training_info, copy_files)`

注册新的训练版本。

**参数**：
- `model_path` (str): 模型路径（HuggingFace格式）
- `gguf_path` (str, optional): GGUF模型路径
- `training_info` (dict, optional): 训练信息
- `copy_files` (bool): 是否复制文件
  - `True`: 传统模式，复制文件到 `trained/` 目录
  - `False`: 引用模式，只记录路径，不复制文件

**返回值**：
- `str`: 版本ID（格式：`v20251024_181017`）

**示例**：
```python
version_id = version_manager.register_new_version(
    model_path="models/qwen/finetuned",
    gguf_path=None,
    training_info={"training_type": "EXISTING_MODEL"},
    copy_files=False  # 引用模式
)
```

#### `list_versions()`

列出所有版本。

**返回值**：
- `list[dict]`: 版本信息列表

**示例**：
```python
versions = version_manager.list_versions()
for v in versions:
    print(f"{v['version_id']}: {v['hf_path']}")
```

#### `get_active_version()`

获取当前激活的版本。

**返回值**：
- `dict | None`: 激活版本信息，如果没有激活版本则返回 `None`

#### `set_active_version(version_id)`

设置激活版本。

**参数**：
- `version_id` (str): 要激活的版本ID

**返回值**：
- `bool`: 是否成功

#### `remove_version(version_id, force)`

删除版本。

**参数**：
- `version_id` (str): 要删除的版本ID
- `force` (bool): 是否强制删除（即使是激活版本）

**返回值**：
- `bool`: 是否成功

**注意**：
- 引用模式的版本：只从列表中移除，不删除原始文件
- 复制模式的版本：删除 `trained/` 目录下的文件

### 2. ModelFineTuner

**文件位置**：`src/training/model_fine_tuner.py`

**职责**：
- 执行模型微调训练
- 训练完成后自动注册版本

**关键代码**：
```python
# 训练完成后自动注册版本
version_manager = self.version_managers[language]
version_id = version_manager.register_new_version(
    model_path=output_dir,  # models/qwen/finetuned
    gguf_path=None,
    training_info=training_info,
    copy_files=False  # 使用引用模式
)
```

### 3. UI模型管理界面

**文件位置**：`simple_ui_fixed.py`

**职责**：
- 显示模型版本列表
- 提供用户交互界面
- 自动检测和注册现有模型

## 工作流程

### 流程1：训练新模型

```
用户在UI中训练模型
    ↓
ModelFineTuner 执行训练
    ↓
保存模型到 models/qwen/finetuned/
    ↓
自动调用 register_new_version(copy_files=False)
    ↓
创建版本记录（引用模式）
    ↓
写入 models/qwen/trained/versions.json
    ↓
UI刷新，显示新版本
```

**关键点**：
- 模型文件保存在 `finetuned/` 目录
- 不复制文件，只记录路径
- 自动注册，无需手动操作

### 流程2：自动检测现有模型

```
用户打开"模型管理"标签页
    ↓
UI调用 refresh_model_info()
    ↓
检查 models/qwen/finetuned/ 是否存在
    ↓
检查是否包含模型文件
    ↓
检查是否已注册到 versions.json
    ↓
如果未注册，自动调用 register_new_version(copy_files=False)
    ↓
创建版本记录
    ↓
显示在版本列表中
```

**关键点**：
- 每次刷新时自动检测
- 处理历史遗留模型
- 无需用户手动操作

### 流程3：激活版本

```
用户在UI中选择版本
    ↓
点击"激活"按钮
    ↓
调用 version_manager.set_active_version(version_id)
    ↓
更新 versions.json 中的 active_version 字段
    ↓
UI刷新，显示激活状态
```

### 流程4：转换为GGUF

```
用户选择版本
    ↓
点击"转换为GGUF"按钮
    ↓
读取版本的 hf_path
    ↓
调用 llama.cpp 的转换工具
    ↓
保存GGUF文件到 models/qwen/quantized/trained/
    ↓
更新版本记录中的 gguf_path
    ↓
UI刷新，显示GGUF路径
```

### 流程5：删除版本

```
用户选择版本
    ↓
点击"删除"按钮
    ↓
检查是否为激活版本
    ↓
如果是激活版本，提示用户
    ↓
调用 version_manager.remove_version(version_id)
    ↓
检查 copy_mode
    ↓
如果是引用模式：只从列表中移除
如果是复制模式：删除 trained/ 目录下的文件
    ↓
更新 versions.json
    ↓
UI刷新
```

**关键点**：
- 引用模式不删除原始文件
- 激活版本需要先切换到其他版本

## 技术实现

### versions.json 文件格式

```json
{
  "versions": [
    {
      "version_id": "v20251024_181017",
      "created_at": "2025-10-24T18:10:17.505146",
      "hf_path": "D:\\...\\models\\qwen\\finetuned",
      "gguf_path": null,
      "training_info": {
        "training_type": "EXISTING_MODEL",
        "config": {
          "models": {...},
          "training": {...},
          "lora": {...}
        }
      },
      "copy_mode": "reference"
    }
  ],
  "active_version": "v20251024_181017"
}
```

**字段说明**：
- `version_id`: 版本唯一标识符
- `created_at`: 创建时间（ISO 8601格式）
- `hf_path`: HuggingFace格式模型路径
- `gguf_path`: GGUF格式模型路径（可选）
- `training_info`: 训练信息和配置
- `copy_mode`: 复制模式（`reference` 或 `copy`）
- `active_version`: 当前激活的版本ID

### 引用模式 vs 复制模式

| 特性 | 引用模式 (copy_files=False) | 复制模式 (copy_files=True) |
|------|---------------------------|--------------------------|
| 文件位置 | `models/qwen/finetuned/` | `models/qwen/trained/vXXXX/` |
| 存储空间 | 不占用额外空间 | 每个版本占用完整空间 |
| 版本数量 | 只能保留1个实际文件 | 可以保留多个版本文件 |
| 删除行为 | 只移除记录，不删除文件 | 删除 `trained/` 下的文件 |
| 适用场景 | 每次训练覆盖前一个版本 | 需要保留多个版本文件 |

**当前项目使用**：引用模式（`copy_files=False`）

**原因**：
1. 节省存储空间
2. 保持模型在原始路径（不影响其他功能）
3. 符合当前使用场景（每次训练覆盖）

### 自动检测逻辑

**代码位置**：`simple_ui_fixed.py` 第7243行

**检测条件**：
1. `models/qwen/finetuned/` 目录存在
2. 包含 `adapter_model.safetensors` 或 `pytorch_model.bin`
3. 未在 `versions.json` 中注册

**注册过程**：
1. 读取 `training_config.json`（如果存在）
2. 创建版本信息
3. 调用 `register_new_version(copy_files=False)`
4. 写入 `versions.json`

**触发时机**：
- 每次调用 `refresh_model_info()` 时
- 打开"模型管理"标签页时
- 点击"刷新"按钮时

## 常见问题

### Q1: 为什么"训练模型版本列表"是空的？

**可能原因**：
1. `models/qwen/finetuned/` 目录不存在
2. 目录中没有模型文件
3. 没有点击"刷新"按钮触发自动检测

**解决方法**：
1. 确认 `models/qwen/finetuned/` 目录存在且包含模型文件
2. 点击"🔄 刷新"按钮
3. 查看控制台是否有错误信息

### Q2: 删除版本后，原始文件还在吗？

**答案**：是的，原始文件仍然保留。

**原因**：
- 当前使用引用模式（`copy_mode: "reference"`）
- 删除操作只移除版本记录，不删除原始文件
- 原始文件位于 `models/qwen/finetuned/`

### Q3: 可以保留多个训练版本吗？

**答案**：可以记录多个版本，但只能保留1个实际文件。

**说明**：
- 引用模式下，所有版本都指向同一个 `finetuned/` 目录
- 每次训练会覆盖之前的模型文件
- 版本记录会保留，但实际文件只有最新的

**如果需要保留多个版本文件**：
- 需要修改为复制模式（`copy_files=True`）
- 但会占用更多存储空间
- 可能影响其他功能（因为路径改变）

### Q4: 如何手动注册现有模型？

**方法1：使用UI**
1. 确保模型在 `models/qwen/finetuned/` 目录
2. 打开"模型管理"标签页
3. 点击"刷新"按钮
4. 自动检测并注册

**方法2：使用代码**
```python
from src.training.model_version_manager import ModelVersionManager

version_manager = ModelVersionManager(base_dir="models/qwen")
version_id = version_manager.register_new_version(
    model_path="models/qwen/finetuned",
    copy_files=False
)
print(f"注册成功: {version_id}")
```

### Q5: versions.json 文件丢失了怎么办？

**答案**：不用担心，会自动重新创建。

**过程**：
1. 打开"模型管理"标签页
2. 点击"刷新"按钮
3. 自动检测 `finetuned/` 目录中的模型
4. 自动创建新的 `versions.json` 文件
5. 注册检测到的模型

### Q6: 如何查看模型文件的实际位置？

**方法1：使用UI**
1. 选择版本
2. 点击"📂 打开文件夹"按钮
3. 文件管理器会打开模型所在目录

**方法2：查看详情**
1. 选择版本
2. 点击"📋 查看详情"按钮
3. 查看"HF路径"字段

**方法3：查看 versions.json**
```bash
cat models/qwen/trained/versions.json
```
