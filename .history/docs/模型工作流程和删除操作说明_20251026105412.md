## 完整的模型工作流程

### 工作流程图

```
1. 下载基础模型
   ↓
2. 训练模型（生成LoRA适配器）
   ↓
3. 合并模型（基础模型 + LoRA适配器）
   ↓
4. 转换为GGUF格式
   ↓
5. 用于推理（视频处理）
```

### 详细步骤

#### 步骤1：下载基础模型
- **操作**：在"设置 → 模型管理"中点击"下载中文模型"或"下载英文模型"
- **结果**：下载HuggingFace格式的预训练模型
- **位置**：`models/qwen2.5-1.5b/fp16/` 或 `models/mistral-7b/fp16/`
- **体积**：约3GB（中文）或约14GB（英文）

#### 步骤2：训练模型
- **操作**：在"训练"标签页中上传训练数据，点击"开始训练"
- **结果**：生成LoRA适配器（只包含训练的参数调整）
- **位置**：`models/qwen/finetuned/` 或 `models/mistral/finetuned/`
- **体积**：约几十MB（只是适配器，不是完整模型）

#### 步骤3：合并模型
- **操作**：训练完成后，系统自动合并基础模型和LoRA适配器
- **结果**：生成完整的HuggingFace格式模型
- **位置**：`models/qwen/merged/` 或 `models/mistral/merged/`
- **体积**：约3GB（和基础模型一样大）
- **说明**：这是转换GGUF的中间产物

#### 步骤4：转换为GGUF格式
- **操作**：在"设置 → 模型管理"中选择训练模型，点击"转换为GGUF"
- **结果**：生成GGUF量化模型
- **位置**：`models/qwen/quantized/*.gguf` 或 `models/mistral/quantized/*.gguf`
- **体积**：约600MB-1.5GB（取决于量化类型）

#### 步骤5：用于推理
- **操作**：在"视频处理"标签页中使用GGUF模型进行推理
- **结果**：生成视频字幕、摘要等

## 各种模型详解

### 1️⃣ 基础模型（Base Model）

**定义**：从HuggingFace下载的预训练模型，是训练的起点。

| 属性 | 值 |
|------|-----|
| **位置** | `models/qwen2.5-1.5b/fp16/` 或 `models/mistral-7b/fp16/` |
| **来源** | 从HuggingFace下载 |
| **格式** | HuggingFace格式（.safetensors） |
| **体积** | 约3GB（中文）或约14GB（英文） |
| **用途** | 用于训练的起点 |
| **是否必需** | ✅ 训练时必需 |

**文件结构**：
```
models/qwen2.5-1.5b/fp16/
├── model.safetensors          # 模型权重（主文件）
├── config.json                # 模型配置
├── tokenizer.json             # 分词器
├── tokenizer_config.json      # 分词器配置
└── ...                        # 其他配置文件
```

---

### 2️⃣ 训练模型/LoRA适配器（Training Model / LoRA Adapter）

**定义**：训练产生的参数调整，只包含训练的增量参数，不是完整模型。

| 属性 | 值 |
|------|-----|
| **位置** | `models/qwen/finetuned/` 或 `models/mistral/finetuned/` |
| **来源** | 训练产生 |
| **格式** | HuggingFace格式（adapter_model.safetensors） |
| **体积** | 约几十MB（只是适配器） |
| **用途** | 存储训练的参数调整 |
| **是否必需** | ✅ 合并模型时必需 |

**文件结构**：
```
models/qwen/finetuned/
├── adapter_model.safetensors  # LoRA适配器权重（主文件）
├── adapter_config.json        # 适配器配置
├── tokenizer.json             # 分词器（从基础模型复制）
└── ...                        # 其他配置文件
```

**重要说明**：
- ⚠️ **LoRA适配器不是完整模型**，只包含训练的增量参数
- ⚠️ **必须和基础模型一起使用**，才能进行推理
- ⚠️ **体积很小**（几十MB），因为只存储了参数调整

---

### 3️⃣ 合并模型（Merged Model）⭐ 重点

**定义**：基础模型 + LoRA适配器 = 合并模型，是完整的HuggingFace格式模型。

| 属性 | 值 |
|------|-----|
| **位置** | `models/qwen/merged/` 或 `models/mistral/merged/` |
| **来源** | 基础模型 + LoRA适配器 = 合并模型 |
| **格式** | HuggingFace格式（.safetensors） |
| **体积** | 约3GB（和基础模型一样大） |
| **用途** | 用于转换为GGUF格式的中间产物 |
| **是否必需** | ✅ 转换GGUF时必需 |

**文件结构**：
```
models/qwen/merged/
├── model.safetensors          # 合并后的模型权重（主文件）
├── config.json                # 模型配置
├── tokenizer.json             # 分词器
├── tokenizer_config.json      # 分词器配置
└── ...                        # 其他配置文件
```

**重要说明**：
- ⚠️ **合并模型 ≠ GGUF模型**
- ⚠️ **合并模型是HuggingFace格式**，不是GGUF格式
- ⚠️ **合并模型是转换GGUF的中间产物**
- ⚠️ **体积和基础模型一样大**（约3GB）

**为什么需要合并模型？**
- LoRA适配器只包含增量参数，不能直接转换为GGUF
- 必须先将基础模型和LoRA适配器合并为完整模型
- 然后才能转换为GGUF格式

---

### 4️⃣ GGUF量化模型（GGUF Quantized Model）

**定义**：从合并模型转换而来的量化模型，用于高效推理。

| 属性 | 值 |
|------|-----|
| **位置** | `models/qwen/quantized/*.gguf` 或 `models/mistral/quantized/*.gguf` |
| **来源** | 从合并模型转换而来 |
| **格式** | GGUF格式（.gguf） |
| **体积** | 约600MB-1.5GB（取决于量化类型） |
| **用途** | 用于推理（视频处理） |
| **是否必需** | ✅ 推理时必需 |

**文件示例**：
```
models/qwen/quantized/
├── trained_20251026_101751_Q4_K_M_f16.gguf  # Q4量化模型（约1.1GB）
├── trained_20251026_102030_Q2_K_f16.gguf    # Q2量化模型（约600MB）
└── trained_20251026_102145_Q6_K_f16.gguf    # Q6量化模型（约1.5GB）
```

**量化类型说明**：
- **Q2_K**：最小体积（约600MB），质量较低
- **Q4_K_M**：最佳平衡（约1.1GB），推荐使用
- **Q6_K**：最高质量（约1.5GB），质量接近原始模型

**重要说明**：
- ⚠️ **GGUF模型是从合并模型转换而来**，不是从基础模型或LoRA适配器直接转换
- ⚠️ **GGUF模型用于推理**，不能用于训练
- ⚠️ **GGUF模型体积小**，推理速度快

## 模型关联关系图

### 依赖关系

```
基础模型 (models/qwen2.5-1.5b/fp16)
    ↓
    ├─→ 训练模型/LoRA适配器 (models/qwen/finetuned)
    │       ↓
    │       └─→ 合并模型 (models/qwen/merged) ← 基础模型 + LoRA适配器
    │               ↓
    │               └─→ GGUF模型 (models/qwen/quantized/*.gguf)
    │
    └─→ 可以重新训练
```

### 文件大小对比

| 模型类型 | 体积 | 说明 |
|---------|------|------|
| **基础模型** | 约3GB | 完整的预训练模型 |
| **训练模型/LoRA适配器** | 约几十MB | 只包含增量参数 |
| **合并模型** | 约3GB | 基础模型 + LoRA适配器 |
| **GGUF模型（Q2_K）** | 约600MB | 最小体积量化 |
| **GGUF模型（Q4_K_M）** | 约1.1GB | 最佳平衡量化 |
| **GGUF模型（Q6_K）** | 约1.5GB | 最高质量量化 |

## 删除操作的影响

### 场景1：删除基础模型

**操作**：在"设置 → 模型管理"中删除基础模型

**删除的文件**：
- ✅ 基础模型（约3GB）
- ✅ 所有合并模型（约3GB）

**保留的文件**：
- ❌ 训练模型/LoRA适配器（约几十MB）
- ❌ GGUF模型（约600MB-1.5GB）

**影响**：
- ❌ **无法再次训练新模型**（因为基础模型被删除了）
- ✅ **可以继续使用GGUF模型进行推理**（GGUF模型仍然存在）
- ❌ **无法重新转换GGUF模型**（因为合并模型被删除了）

**适用场景**：
- 你已经完成了训练和转换
- 你只需要使用GGUF模型进行推理
- 你想节省空间（删除约6GB）

---

### 场景2：删除训练模型

**操作**：在"设置 → 模型管理"中删除训练模型

**删除的文件**：
- ✅ 训练模型/LoRA适配器（约几十MB）
- ✅ 合并模型（约3GB）
- ✅ GGUF模型（约600MB-1.5GB）

**保留的文件**：
- ❌ 基础模型（约3GB）

**影响**：
- ✅ **可以重新训练新模型**（基础模型仍然存在）
- ❌ **无法使用之前的GGUF模型进行推理**（GGUF模型被删除了）
- ❌ **之前的训练结果丢失**（训练模型被删除了）

**适用场景**：
- 你对训练结果不满意，想重新训练
- 你想清理所有训练相关的文件
- 你想节省空间（删除约3.6GB）

---

### 场景3：只删除GGUF模型

**操作**：在"设置 → 模型管理"中删除GGUF模型

**删除的文件**：
- ✅ GGUF模型（约600MB-1.5GB）

**保留的文件**：
- ❌ 基础模型（约3GB）
- ❌ 训练模型/LoRA适配器（约几十MB）
- ❌ 合并模型（约3GB）

**影响**：
- ✅ **可以重新转换GGUF模型**（合并模型仍然存在）
- ❌ **无法使用GGUF模型进行推理**（GGUF模型被删除了）
- ✅ **训练结果保留**（训练模型仍然存在）

**适用场景**：
- 你想尝试不同的量化类型
- 你想节省空间（删除约600MB-1.5GB）
- 你可以随时重新转换GGUF模型

---

### 场景4：清理所有模型

**操作**：依次删除训练模型和基础模型

**删除的文件**：
- ✅ 基础模型（约3GB）
- ✅ 训练模型/LoRA适配器（约几十MB）
- ✅ 合并模型（约3GB）
- ✅ GGUF模型（约600MB-1.5GB）

**保留的文件**：
- ✅ 无

**影响**：
- ❌ **无法训练新模型**
- ❌ **无法使用GGUF模型进行推理**
- ✅ **节省最多空间**（删除约6.6GB-7.5GB）

**适用场景**：
- 你想完全清理项目
- 你想重新开始

## 常见问题解答

### Q1：合并模型是什么？和GGUF模型有什么区别？

**A1**：
- **合并模型**：基础模型 + LoRA适配器 = 合并模型
  - 格式：HuggingFace格式（.safetensors）
  - 体积：约3GB
  - 用途：转换GGUF的中间产物
  
- **GGUF模型**：从合并模型转换而来的量化模型
  - 格式：GGUF格式（.gguf）
  - 体积：约600MB-1.5GB
  - 用途：用于推理

**关键区别**：
- 合并模型是HuggingFace格式，GGUF模型是GGUF格式
- 合并模型体积大，GGUF模型体积小
- 合并模型是中间产物，GGUF模型是最终产物

---

### Q2：为什么删除基础模型后，项目体积只下降了部分？

**A2**：
- **之前的Bug**：删除基础模型时，没有删除合并模型
- **结果**：合并模型（约3GB）仍然存在，导致项目体积只下降了部分
- **修复**：现在删除基础模型时，会自动删除所有合并模型
- **效果**：项目体积会完全下降（删除约6GB）

---

### Q3：删除训练模型后，GGUF模型列表为什么消失了？

**A3**：
- **原因**：删除训练模型时，系统会自动删除对应的GGUF模型
- **设计**：GGUF模型是从训练模型转换而来的，删除训练模型后，GGUF模型也应该被删除
- **结果**：GGUF列表消失是正确的行为，不是Bug

---

### Q4：我只想删除GGUF模型，不想删除训练模型，怎么办？

**A4**：
- **操作**：在"设置 → 模型管理"的"GGUF推理模型"列表中，选择GGUF模型，点击"删除"
- **结果**：只删除GGUF模型，不影响训练模型和基础模型
- **恢复**：可以随时重新转换GGUF模型

---

### Q5：我想节省空间，应该删除哪些模型？

**A5**：
- **如果你只需要推理**：删除基础模型和合并模型（节省约6GB）
- **如果你想重新训练**：删除训练模型、合并模型和GGUF模型（节省约3.6GB）
- **如果你想尝试不同量化类型**：只删除GGUF模型（节省约600MB-1.5GB）
- **如果你想完全清理**：删除所有模型（节省约6.6GB-7.5GB）

---

### Q6：删除模型后，可以恢复吗？

**A6**：
- ❌ **无法恢复**：删除操作是不可逆的
- ✅ **可以重新生成**：
  - 基础模型：重新下载
  - 训练模型：重新训练
  - 合并模型：重新合并
  - GGUF模型：重新转换

---

### Q7：我应该保留哪些模型？

**A7**：
- **如果你只需要推理**：只保留GGUF模型
- **如果你可能重新训练**：保留基础模型
- **如果你想尝试不同量化类型**：保留合并模型
- **如果你想完整备份**：保留所有模型

---

## 📝 总结

### 核心概念

1. **基础模型**：从HuggingFace下载的预训练模型（约3GB）
2. **训练模型/LoRA适配器**：训练产生的参数调整（约几十MB）
3. **合并模型**：基础模型 + LoRA适配器（约3GB）
4. **GGUF模型**：从合并模型转换而来的量化模型（约600MB-1.5GB）

### 关键区别

- **合并模型 ≠ GGUF模型**
- **合并模型是HuggingFace格式**，GGUF模型是GGUF格式
- **合并模型是中间产物**，GGUF模型是最终产物

### 删除建议

- **删除基础模型**：节省约6GB，但无法再次训练
- **删除训练模型**：节省约3.6GB，但无法使用之前的GGUF模型
- **删除GGUF模型**：节省约600MB-1.5GB，可以随时重新转换
- **清理所有模型**：节省约6.6GB-7.5GB，完全清理项目
